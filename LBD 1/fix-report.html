About the evidence on this page

There are no screenshots here, and that is deliberate. The fixes were authored in an environment with no browser and no Node runtime, so the game was never rendered. Any screenshot on this page would have been fabricated rather than captured.

What is here instead is measurement: clip durations read from the Vorbis headers of your own audio files, node geometry read from js/data.js, and arithmetic against the 1920×1080 stage. Those numbers are real and reproducible.

There are two different claims on this page, and they should not be read as one. “Shipped” is confirmed — each change was read back out of origin/main after the push, so the code described here is genuinely what is on the branch. “Works” is not confirmed. scripts/check-all.mjs and qa/smoke-test.mjs have never been run against it and the game has never been rendered, so nothing below has been seen behaving correctly.

The checklist at the bottom is the work that still has to happen on a real device. Until it is done, treat every entry here as a defect correctly diagnosed and a fix correctly written — not as a fix proven to work.

Narration out of sync with the item-name scrolls

Root cause

BUG 2

“Try again” gave no sign it wanted pressing

Root cause

The button popped in once over 0.3 s and then stopped moving forever. That pop was the entire affordance — half a second later, the one control that unlocks the items was indistinguishable from scenery, at the exact moment the child is already stuck. All five levels; the Next buttons at least had a hint hand, this had nothing.

Fix

A shared tap treatment now used by 20 buttons: a springy hop (≈10 px lift + swell, once every 1.5 s) that continues until the button is pressed. Rest pose is captured once, so repeated retries can never make a button drift bigger or smaller. controllers.js · makeTappable

BUG 3

Hint hand cut off by the bottom of the screen

Root cause

The hand sprite draws its hand in the lower-middle of a mostly-empty 1200×1200 frame — fingertip at 52 % of the frame height, wrist at 80 %. Centring that box on a button does not put the finger on the button: it drops the fingertip into the button's lower half and hangs the palm far below. The Part-2 and Part-4 Next buttons sit at y = 1016 in a 1080-tall stage, leaving only 64 px beneath them.

BUG 5

Final screen had no button and no hint at all

Root cause

Two faults stacked. isLastLevel short-circuits before any Next button is shown, so the completion screen alone had no forward affordance and never requested a hint. And even switching the button on would not have worked: it is authored deep inside the Part-4 subtree, while the final picture is a direct child of the level root — a later sibling that paints straight over it.

Fix

The button is re-hosted above the final picture (the same technique the ghost hand uses to survive a part change) and rebuilt in CSS as a festival-gold pill in the bottom-right corner, 60 px clear of both edges, with a light travelling around its border. It inherits the shared hop, press and hand hint. controllers.js · showFinalNext

BUG 6

Completion sparkles stuttered and cut off

Root cause — six of them, all on one frame
#FaultEffect
1Burst fired on the same frame three nodes were hiddenlayout change + 60 elements in one frame
22nd container measured after the 1st burst was in the DOMforced synchronous layout
3Each particle appended separately30 insertions per burst
4will-change on every particle60 compositor layers at once
5One shared lifetime from one start timethe cloud vanished on a single frame
6Same thrash in the final-screen celebrationthree forced layouts
Fix

Measure every centre before creating anything; defer the first burst one frame so the scene change is painted first; stagger the containers ~110 ms apart; one DocumentFragment insertion per burst; drop will-change; and give every particle its own lifetime (0.7×–1.3×) so the sparkles taper away instead of blinking out.

BUG 7

Blue browser touch highlight over every tapped element

Root cause — two separate sources

-webkit-tap-highlight-color was set nowhere in the project, so Chrome and WebKit painted their default box over every tap. Separately, the engine gives every tap target tabindex="0" for keyboard access — so a tap also focuses it, and several Android WebViews draw a blue outline on :focus that stays behind after the tap. Fixing only the first would have left the second.

Fix

Highlight set to transparent on the universal selector (some WebViews honour it only on the element actually tapped, and these targets nest deep), and the focus outline suppressed — placed before the :focus-visible rule so the keyboard ring still works. style.css

BUG 8

Hand cursor over the whole intro background

Root cause

n2_Intro_1 — the title backdrop — is a full-screen node (anchors 0,0 → 1,1, the whole 1920×1080 stage) that carries the title art and a Unity Button component. The engine gave every Button component a hand cursor. That button does nothing: its only authored call is an animator Play, which the flow wiring ignores.

Fix

BUG 9

The hand slid behind the “Next” label

Root cause — introduced by the gold button

The label carried z-index: 1 so it would sit above the travelling border light. But .node is position: absolute with no z-index, so it creates no stacking context — and that z-index: 1 escaped into the root stacking context, where it outranks every z-index: auto element on the stage. The hint hand is one of those, so the word painted over the hand.

Fix

isolation: isolate on the button builds a stacking context without touching layout: inside, the label still sits above the border light; outside, the button stacks by DOM order again, and n519_hand is a later root sibling than the level. style.css · .rb-magic-btn · c474d61

BUG 10

Two celebration sounds on the final drop

Root cause — also mine

checkPart4Completion runs in the same frame as the final correct drop, which has just started the authored magical chime — 2.81 s of it. The three-note fanfare added there played directly on top, so clearing the stage was heard as two celebrations at once.

Fix

The fanfare is gone. The chime is the stage-clear sound and the stars are its picture. This restores the rule the rest of this work follows: add a sound only where the game was silent, never on top of an authored one. c8a6d26

BUG 11

The game paused after tapping Next

Root cause — two flat waits, pre-existing

Part 3 sat for 1.1 s doing nothing before its panel even began to slide, then took a further 1.0 s before a word was spoken. The 1.1 s existed so Part 2 could finish leaving. Part 4 had a flat 1 s of its own.
